# CoreTalk

Корпоративный мессенджер **MB Core Vienas** на протоколе Matrix. Первый заказчик
и обкатка — BritiTrade (аптечная сеть, 200+ аптек, ~1000 сотрудников).

Это **форк клиента [Sable](https://github.com/SableClient/Sable)** (React + Tauri 2),
взятый с тега `v1.21.0`. Один код на четыре платформы: страница в браузере,
настольное приложение (Windows, macOS, Linux), iOS и Android.

Сервер — [Tuwunel](https://github.com/matrix-construct/tuwunel), развёрнут ролью
Ansible `tuwunel` в репозитории `coreone-io/core1-dev`.

## Устройство веток

| Ветка | Что в ней |
|---|---|
| `upstream` | зеркало апстрима: сюда приезжают его теги без единой нашей правки |
| `main` | принятый тег апстрима плюс наши коммиты поверх |

Слой наших правок **тонкий намеренно**: марка конфигом, перевод каталогом строк,
пуш конфигом и своим шлюзом. Апстрим держит тысячи коммитов за полгода, и толстый
слой конфликтовал бы на каждом слиянии.

## Настройка клиента

Сервер и повадки задаёт `config.json` — он читается ВО ВРЕМЯ РАБОТЫ, а не при
сборке: сменить сервер можно, заменив файл в раздаче, без пересборки. Имя
продукта — исключение, оно попадает в сборку.

`allowRegistration: false` говорит, что учётные записи заводятся не здесь, а
входом CoreOne (authentik). Клиент тогда не спрашивает у сервера, открыта ли
регистрация: апстрим узнаёт это НАМЕРЕННО неудачным запросом
`POST /_matrix/client/v3/register` и читает ответ по коду ошибки — при закрытой
регистрации сервер отвечает 403, и браузер писал эту ошибку в консоль на каждой
загрузке страницы входа. Заодно исчезает ссылка «Register»: апстрим показывал её
даже при 403, если сервер предлагает вход через внешнего поставщика — у нас
предлагает, а регистрацию всё равно не даёт.

Поле необязательное: не задано — клиент ведёт себя как апстрим и спрашивает
сервер.
